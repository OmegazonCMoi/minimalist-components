# minimalist-components

Minimalist UI components for **Next.js** + **Tailwind CSS 4**.

Components are **copied into your project** (like shadcn/ui) so you own the code and can edit it freely. A small CLI handles install.

---

## Requirements

- Node.js 18+
- Next.js 14+ (App Router recommended)
- React 18+
- Tailwind CSS 4
- TypeScript path alias `@/*` → project root (default Next.js setup)

---

## Quick start

```bash
npx minimalist-components init
npx minimalist-components add button
```

Then import from your local copy:

```tsx
import { Button } from "@/components/ui/button";

export default function Page() {
  return <Button style="primary">Save</Button>;
}
```

Install peer libraries when the CLI asks for them (example):

```bash
npm install framer-motion lucide-react
```

`framer-motion` and `lucide-react` also ship as dependencies of this package. The CLI still suggests adding them to **your** app so imports resolve cleanly (especially with pnpm).

## CLI

```bash
npx minimalist-components init
npx minimalist-components list
npx minimalist-components add button
npx minimalist-components add badge input select
npx minimalist-components add alert-dialog   # also pulls button + lib/motion
```

| Command | Description |
| --- | --- |
| `init` | Creates `minimalist.json`, component & lib folders |
| `add <name…>` | Copies component(s) + shared utils into your app |
| `list` | Shows every installable component |

**Flags**

- `--yes` / `-y` — non-interactive defaults (`init`), keep existing files on conflict (`add`)
- `--force` — overwrite existing files (`add`)

### Config (`minimalist.json`)

Generated by `init`:

```json
{
  "componentsDir": "components/ui",
  "libDir": "lib",
  "aliases": {
    "components": "@/components/ui",
    "lib": "@/lib"
  },
  "typescript": true
}
```

## How it works

1. Source of truth lives in this repo under `components/` and `lib/`.
2. `npm run sync:templates` snapshots installable files into `templates/`.
3. The published package ships `bin/`, `dist/cli.cjs`, and `templates/`.
4. `add` copies templates into **your** tree and rewrites imports to your aliases.

You are not locked into a runtime dependency on this package for UI — only the CLI (and optional docs site) lives on npm.

## Local development (this repo)

```bash
npm install
npm run dev          # docs site → http://localhost:3000
npm run build:cli    # sync templates + build CLI / library
npm run sync:templates
```

| Path | Role |
| --- | --- |
| `app/` | Documentation site (Next.js) |
| `components/` | UI source used by the docs |
| `lib/` | Shared utilities (`motion.ts`, …) |
| `cli/` | CLI implementation |
| `registry/` | Component registry |
| `templates/` | Packaged copies for `npx … add` |
